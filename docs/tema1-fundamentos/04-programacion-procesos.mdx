# Programación con Procesos y Sincronización
En esta sección, veremos cómo crear y gestionar procesos desde una aplicación, así como los métodos de comunicación y sincronización entre ellos.

Vamos a utilizar Kotlin como lenguaje de programación. Existen otras alternativas, como Python o C/C++, pero Kotlin nos permite ilustrar los conceptos de manera clara y concisa. Además, viniendo de Java, la sintaxis y las herramientas son familiares.  

## Creación y Gestión de Procesos

### La clase `Process`

La clase `Process` representa un proceso en ejecución. Esta clase proporciona métodos para interactuar con el proceso, como obtener su salida, error y código de salida.

Aquí hay un ejemplo de cómo usar la clase ``Process``:
```kotlin
import java.io.File
import java.io.InputStreamReader
import java.io.BufferedReader
import java.lang.ProcessBuilder
import java.util.concurrent.TimeUnit
import kotlin.system.exitProcess

fun main() {
    // Crear un proceso para ejecutar el comando 'ls -l'
    val processBuilder = ProcessBuilder("ls", "-l")
    processBuilder.directory(File("/")) // Establecer el directorio de trabajo
    processBuilder.redirectErrorStream(true) // Redirigir errores al flujo de salida

    try {
        val process = processBuilder.start() // Iniciar el proceso, el método start() devuelve un objeto Process

        // Leer la salida del proceso
        val reader = BufferedReader(InputStreamReader(process.inputStream))
        var line: String?
        while (reader.readLine().also { line = it } != null) {
            println(line)
        }

        // Esperar a que el proceso termine
        val exitCode = process.waitFor()
        println("Proceso terminado con código de salida: $exitCode")
    } catch (e: Exception) {
        e.printStackTrace()
    }
}
```

En este ejemplo, creamos un proceso que ejecuta el comando `ls -l` en el directorio raíz. Utilizamos `ProcessBuilder` para configurar y lanzar el proceso, y luego leemos su salida.

La gestión de procesos incluye la capacidad de esperar a que un proceso termine, obtener su código de salida y manejar errores.

#### Métodos y ejemplos de la clase ``Process``

En la siguiente tabla podemos ver los métodos más relevantes de la clase para manejar procesos:

| Método                     | Descripción                                                  |
|----------------------------|--------------------------------------------------------------|
| `waitFor()`                | Espera a que el proceso termine y devuelve su código de salida. |
| `waitFor(timeout, unit)`   | Espera como máximo el tiempo indicado; devuelve `true` si el proceso terminó. |
| `getInputStream()`         | Devuelve un flujo de entrada para leer la salida del proceso. |
| `getErrorStream()`         | Devuelve un flujo de entrada para leer los errores del proceso. |
| `getOutputStream()`        | Devuelve un flujo de salida para escribir en la entrada estándar del proceso. |
| `destroy()`                | Solicita la finalización del proceso (en Linux envía `SIGTERM`). |
| `destroyForcibly()`        | Fuerza la finalización inmediata del proceso (en Linux envía `SIGKILL`). |
| `isAlive()`                | Devuelve true si el proceso aún está en ejecución.           |
| `exitValue()`              | Devuelve el código de salida (lanza excepción si aún no ha terminado). |
| `pid()`                    | Devuelve el identificador (PID) del proceso.                 |
| `toHandle()`               | Devuelve el `ProcessHandle` asociado al proceso.             |
| `onExit()`                 | Devuelve un `CompletableFuture<Process>` que se completa al terminar el proceso. |

:::info Propiedades en Kotlin
Desde Kotlin, los métodos Java `getXxx()` se pueden usar como propiedades: `process.inputStream` equivale a `process.getInputStream()`, y `process.isAlive` a `process.isAlive()`.
:::

### La clase ``ProcessBuilder``

A diferencia de ``Process``, la clase ``ProcessBuilder`` se utiliza para crear y configurar un nuevo proceso antes de iniciarlo. Proporciona una forma más flexible y poderosa de construir procesos, permitiendo establecer el entorno, redirigir flujos de entrada/salida y configurar otras opciones.

En Kotlin, podemos crear y gestionar procesos utilizando la clase `ProcessBuilder`. Aquí hay un ejemplo básico:
```kotlin
import java.io.File
import java.io.InputStreamReader
import java.io.BufferedReader
import java.lang.ProcessBuilder
import java.util.concurrent.TimeUnit
import kotlin.system.exitProcess

fun main() {
    // Crear un proceso para ejecutar el comando 'ls -l'
    val processBuilder = ProcessBuilder("ls", "-l")
    processBuilder.directory(File("/")) // Establecer el directorio de trabajo
    processBuilder.redirectErrorStream(true) // Redirigir errores al flujo de salida

    try {
        val process = processBuilder.start() // Iniciar el proceso

        // Leer la salida del proceso
        val reader = BufferedReader(InputStreamReader(process.inputStream))

        }

        val exitCode = process.waitFor()
        println("Proceso terminado con código de salida: $exitCode")
    } catch (e: Exception) {
        e.printStackTrace()
    }
}
```

En este ejemplo, creamos un proceso que ejecuta el comando `ls -l` en el directorio raíz. Utilizamos `ProcessBuilder` para configurar y lanzar el proceso, y luego leemos su salida.    

La gestión de procesos incluye la capacidad de esperar a que un proceso termine, obtener su código de salida y manejar errores.

:::tip La clase ``ProcessBuilder``
La clase `ProcessBuilder` es una herramienta poderosa para crear y gestionar procesos en Java y Kotlin. Permite configurar el entorno del proceso, redirigir la entrada y salida, y manejar errores de manera eficiente.
:::

Los métodos más utilizados de la clase `ProcessBuilder`son los que podemos encontrar en la siguiente tabla:

| Método                       | Descripción                                                  |

### La clase ``Runtime`` para la creación de procesos

A diferencia de la clase ``ProcessBuilder``, la clase ``Runtime`` es más simple y directa, pero ofrece menos control sobre el proceso.

Aquí hay un ejemplo de cómo usar la clase ``Runtime`` para ejecutar un comando:

```kotlin
import java.io.BufferedReader
import java.io.InputStreamReader

fun main() {
    try {
        val process = Runtime.getRuntime().exec(arrayOf("ls", "-l"))
        val reader = BufferedReader(InputStreamReader(process.inputStream))
        var line: String?
        while (reader.readLine().also { line = it } != null) {
            println(line)
        }
        val exitCode = process.waitFor()
        println("Proceso terminado con código de salida: $exitCode")
    } catch (e: Exception) {
        e.printStackTrace()
    }
}
```

:::info `ProcessBuilder` vs `Runtime`
La principal diferencia entre `ProcessBuilder` y `Runtime` radica en el nivel de control que ofrecen sobre el proceso. De hecho, internamente `Runtime.exec()` crea un `ProcessBuilder`. `ProcessBuilder` permite una configuración más detallada del entorno del proceso, incluyendo la redirección de flujos de entrada/salida y la modificación del entorno del proceso. Por otro lado, `Runtime` es más simple y directo, pero ofrece menos opciones de configuración.

La decisión de cuándo utilizar una opción u otra depende de los requisitos específicos de la aplicación. Si se necesita un control fino sobre el proceso y su entorno, `ProcessBuilder` es la mejor opción. Si se busca una solución rápida y sencilla, `Runtime` puede ser suficiente.
:::

:::warning `exec(String)` está obsoleto
La versión `Runtime.exec(String)`, que recibe el comando completo en una sola cadena, está marcada como obsoleta (*deprecated*) desde Java 18, porque divide el texto por espacios y falla con rutas o argumentos que los contienen. Hay que usar la versión que recibe un array (`exec(arrayOf("ls", "-l"))`) o, mejor aún, `ProcessBuilder`.
:::

### La clase ``ProcessHandle`` 
La clase `ProcessHandle` proporciona una forma de interactuar con procesos en ejecución. Permite obtener información sobre un proceso, como su ID, estado y tiempo de ejecución. Aquí hay un ejemplo de cómo usar la clase `ProcessHandle`:

```kotlin
import java.lang.ProcessBuilder
import java.util.concurrent.TimeUnit
import kotlin.system.exitProcess
fun main() {
    // Crear un proceso para ejecutar el comando 'sleep 10'
    val processBuilder = ProcessBuilder("sleep", "10")
    try {
        val process = processBuilder.start() // Iniciar el proceso
        val processHandle = process.toHandle() // Obtener el ProcessHandle del proceso

        println("Proceso iniciado con PID: ${processHandle.pid()}")

        // Esperar a que el proceso termine
        val exitCode = process.waitFor()
        println("Proceso terminado con código de salida: $exitCode")
    } catch (e: Exception) {
        e.printStackTrace()
    }
}
```

En este ejemplo, creamos un proceso que ejecuta el comando `sleep 10`. Utilizamos `ProcessBuilder` para iniciar el proceso y luego obtenemos su `ProcessHandle` para acceder a información sobre el proceso, como su ID.

#### Métodos y ejemplos de la clase ``ProcessHandle``
Los métodos más utilizados de la clase `ProcessHandle` son los que podemos encontrar en la siguiente tabla:
| Método                       | Descripción                                                  |
|------------------------------|--------------------------------------------------------------|
| `pid()`                      | Devuelve el ID del proceso.                                  |
| `isAlive()`                  | Devuelve true si el proceso aún está en ejecución.           |
| `info()`                     | Devuelve un objeto `ProcessHandle.Info` con información sobre el proceso. |
| `children()`                 | Devuelve un flujo de los procesos hijos del proceso.        |
| `descendants()`              | Devuelve un flujo con todos los descendientes (hijos, nietos…). |
| `parent()`                   | Devuelve un `Optional<ProcessHandle>` con el proceso padre, si existe. |
| `destroy()`                  | Solicita la finalización del proceso.                        |
| `destroyForcibly()`          | Fuerza la finalización inmediata del proceso.                |
| `onExit()`                   | Devuelve un `CompletableFuture<ProcessHandle>` que se completa cuando el proceso termina. |    

Aquí hay un ejemplo de cómo usar algunos de estos métodos:

```kotlin
import java.lang.ProcessBuilder
import java.util.concurrent.TimeUnit
import kotlin.system.exitProcess
fun main() {
    // Crear un proceso para ejecutar el comando 'sleep 10'
    val processBuilder = ProcessBuilder("sleep", "10")
    try {
        val process = processBuilder.start() // Iniciar el proceso
        val processHandle = process.toHandle() // Obtener el ProcessHandle del proceso
        println("Proceso iniciado con PID: ${processHandle.pid()}")
        println("¿El proceso está vivo? ${processHandle.isAlive()}")
        val info = processHandle.info()
        println("Comando: ${info.command().orElse("desconocido")}")
        println("Usuario: ${info.user().orElse("desconocido")}")
        println("Inicio: ${info.startInstant().orElse(null)}")
        // Esperar a que el proceso termine
        val exitCode = process.waitFor()
        println("Proceso terminado con código de salida: $exitCode")
    } catch (e: Exception) {
        e.printStackTrace()
    }
}
```

`ProcessHandle` también permite consultar procesos que no hemos lanzado nosotros. Por ejemplo, podemos obtener el proceso actual o recorrer todos los procesos del sistema:

```kotlin
fun main() {
    val actual = ProcessHandle.current()
    println("PID de esta JVM: ${actual.pid()}")

    ProcessHandle.allProcesses()
        .filter { it.info().command().isPresent }
        .limit(10)
        .forEach { println("${it.pid()} -> ${it.info().command().get()}") }
}
```

### Lanzamiento de procesos en segundo plano

Lanzar un proceso en segundo plano significa que el programa padre **no se queda esperando** a que termine: sigue trabajando y, si le interesa, recibe un aviso cuando el hijo acaba. Si no nos interesa su salida, podemos descartarla con `ProcessBuilder.Redirect.DISCARD` (equivale a redirigir a `/dev/null` en Unix o a `NUL` en Windows):

```kotlin
fun main() {
    val process = ProcessBuilder("sleep", "5")
        .redirectOutput(ProcessBuilder.Redirect.DISCARD) // Descartar la salida
        .redirectError(ProcessBuilder.Redirect.DISCARD)  // Descartar los errores
        .start()

    println("Proceso iniciado en segundo plano con PID: ${process.pid()}")

    // Registrar qué hacer cuando termine, sin bloquear al padre
    process.onExit().thenAccept { p ->
        println("El proceso ${p.pid()} ha terminado con código ${p.exitValue()}")
    }

    // Mientras tanto, el programa padre sigue trabajando
    repeat(3) { i ->
        println("El padre sigue trabajando... ($i)")
        Thread.sleep(1000)
    }

    process.waitFor() // Solo para que el ejemplo no termine antes que el hijo
}
```
En este ejemplo, el proceso `sleep 5` se ejecuta en segundo plano mientras el padre sigue mostrando mensajes. Con `onExit()` registramos una acción que se ejecutará cuando el hijo termine, sin necesidad de bloquear al padre con `waitFor()`.

### Lanzamiento de procesos en primer plano

Lanzar un proceso en primer plano significa que el programa padre **espera a que termine** antes de continuar. Si además queremos que el proceso hijo use directamente la consola del padre (para mostrar su salida o leer del teclado), podemos usar `inheritIO()`:

```kotlin
fun main() {
    val process = ProcessBuilder("ping", "-c", "3", "localhost")
        .inheritIO() // El hijo escribe directamente en la consola del padre
        .start()

    println("Proceso iniciado con PID: ${process.pid()}")

    // El padre se bloquea hasta que el hijo termine
    val exitCode = process.waitFor()
    println("Proceso terminado con código de salida: $exitCode")
}
```
En este ejemplo, la salida de `ping` aparece directamente en la consola y el padre no continúa hasta que el proceso termina.

:::warning Leer siempre la salida o redirigirla
Si un proceso hijo escribe mucho en su salida y nadie la lee (ni se redirige ni se hereda), el búfer del sistema operativo se llena y el hijo se queda **bloqueado** para siempre. Por eso, siempre hay que leer `inputStream`/`errorStream`, redirigirlos a un fichero, descartarlos (`Redirect.DISCARD`) o heredarlos (`inheritIO()`).
:::

### Ejecución de programas o scripts externos

Para ejecutar programas o scripts externos desde una aplicación Kotlin, podemos utilizar la clase `ProcessBuilder`. Aquí hay un ejemplo de cómo hacerlo:

```kotlin

import java.lang.ProcessBuilder
import java.util.concurrent.TimeUnit
import kotlin.system.exitProcess

    // Crear un proceso para ejecutar un script externo
    val processBuilder = ProcessBuilder("path/to/your/script.sh")

    processBuilder.redirectErrorStream(true) // Redirigir errores al flujo de salida

    try {
        val process = processBuilder.start() // Iniciar el proceso

        // Leer la salida del proceso
        val reader = BufferedReader(InputStreamReader(process.inputStream))
        var line: String?
        while (reader.readLine().also { line = it } != null) {
            println(line)
        }

        // Esperar a que el proceso termine
        val exitCode = process.waitFor()
        println("Proceso terminado con código de salida: $exitCode")
    } catch (e: Exception) {
        e.printStackTrace()
    }
}
```

En este ejemplo, creamos un proceso que ejecuta un script externo ubicado en `path/to/your/script.sh`. Utilizamos `ProcessBuilder` para configurar y lanzar el proceso, y luego leemos su salida.

Esto nos puede servir para ejecutar cualquier programa o script externo desde nuestra aplicación Kotlin, lo que nos permite integrar funcionalidades adicionales o automatizar tareas.

Incluso podemos pasar argumentos al script o programa externo de la siguiente manera:


En este ejemplo, pasamos dos argumentos (`arg1` y `arg2`) al script externo. Estos argumentos pueden ser utilizados dentro del script para modificar su comportamiento o procesar datos específicos.

Combinando estos conceptos, podemos crear aplicaciones Kotlin que interactúen con otros programas o scripts, lo que nos permite ampliar las capacidades de nuestras aplicaciones y automatizar tareas de manera eficiente.  

## Comunicación entre procesos

Existen diversas formas de comunicación entre procesos, entre las que se incluyen:

- **Pipes**: Permiten la comunicación unidireccional entre procesos. Un proceso puede escribir en un pipe y otro proceso puede leer de él.
- **Sockets**: Proporcionan una comunicación bidireccional entre procesos, incluso si están en diferentes máquinas.
- **Memoria compartida**: Permite que varios procesos accedan a la misma región de memoria, lo que facilita la comunicación rápida entre ellos.

### Pipes

Los **pipes** son una forma de comunicación unidireccional entre procesos. Permiten que un proceso escriba datos en un pipe, que luego pueden ser leídos por otro proceso. En Kotlin, se pueden utilizar pipes a través de flujos de entrada/salida.

Aquí hay un ejemplo de cómo usar pipes en Kotlin:

```kotlin
import java.io.BufferedReader
import java.io.InputStreamReader
import java.io.OutputStreamWriter
import java.lang.ProcessBuilder

fun main() {
    // Crear un proceso para ejecutar el comando 'grep "kotlin"'
    val processBuilder = ProcessBuilder("grep", "kotlin")
    val process = processBuilder.start()

    // Escribir en el pipe de entrada del proceso
    val writer = OutputStreamWriter(process.outputStream)
    writer.write("kotlin es un lenguaje de programación\n")
    writer.write("java es otro lenguaje de programación\n")
    writer.flush()
    writer.close()

    // Leer la salida del proceso
    val reader = BufferedReader(InputStreamReader(process.inputStream))
    var line: String?
    while (reader.readLine().also { line = it } != null) {
        println(line)
    }

    // Esperar a que el proceso termine
    val exitCode = process.waitFor()
    println("Proceso terminado con código de salida: $exitCode")
}
```

### Sockets

A diferencia de las *pipes*, los **Sockets** proporcionan una comunicación bidireccional entre procesos, incluso si están en diferentes máquinas. Los sockets permiten que un proceso envíe y reciba datos a través de una conexión de red.

Aquí hay un ejemplo de cómo usar sockets en Kotlin:

```kotlin
import java.io.BufferedReader
import java.io.InputStreamReader
import java.io.PrintWriter
import java.net.ServerSocket
import java.net.Socket

fun main() {
    // Iniciar un servidor de sockets
    val server = ServerSocket(9999)
    println("Esperando conexiones...")
    val client = server.accept()
    println("Cliente conectado: ${client.inetAddress}")

    // Leer datos del cliente
    val reader = BufferedReader(InputStreamReader(client.inputStream))
    var line: String?
    while (reader.readLine().also { line = it } != null) {
        println("Recibido del cliente: $line")
    }

    // Cerrar conexiones
    reader.close()
    client.close()
    server.close()
}
```

:::

### Memoria compartida

Otra opción de comunicación entre procesos es la memoria compartida. Al utilizar memoria compartida, varios procesos pueden acceder a la misma región de memoria, lo que facilita la comunicación rápida entre ellos, ya que los datos no tienen que copiarse de un proceso a otro.

En sistemas operativos como Linux, la memoria compartida se gestiona con llamadas al sistema como `shmget`/`shmat` o `shm_open`/`mmap`. La JVM no permite usar esas llamadas directamente, pero sí ofrece **ficheros mapeados en memoria** (`MappedByteBuffer`): el sistema operativo carga el fichero en memoria y todos los procesos que lo mapean comparten las mismas páginas. Es la forma habitual de usar memoria compartida desde Java y Kotlin.

Aquí hay un ejemplo con dos programas: uno escribe en la memoria compartida y otro lee de ella.

```kotlin title="Escritor.kt"
import java.nio.channels.FileChannel
import java.nio.file.Path
import java.nio.file.StandardOpenOption.*

fun main() {
    val fichero = Path.of("/tmp/memoria_compartida.dat")

    FileChannel.open(fichero, CREATE, READ, WRITE).use { canal ->
        // Mapear 1024 bytes del fichero en memoria
        val memoria = canal.map(FileChannel.MapMode.READ_WRITE, 0, 1024)

        val mensaje = "Hola desde la memoria compartida".toByteArray()
        memoria.putInt(0, mensaje.size)     // Primero la longitud del mensaje
        memoria.put(4, mensaje)             // Después el contenido
        println("Mensaje escrito en la memoria compartida")
    }
}
```

```kotlin title="Lector.kt"
import java.nio.channels.FileChannel
import java.nio.file.Path
import java.nio.file.StandardOpenOption.READ

fun main() {
    val fichero = Path.of("/tmp/memoria_compartida.dat")

    FileChannel.open(fichero, READ).use { canal ->
        val memoria = canal.map(FileChannel.MapMode.READ_ONLY, 0, 1024)

        val longitud = memoria.getInt(0)
        val bytes = ByteArray(longitud)
        memoria.get(4, bytes)
        println("Leído de la memoria compartida: ${String(bytes)}")
    }
}
```

Si ejecutamos primero `Escritor` y después `Lector` (son dos procesos distintos, dos JVM diferentes), el lector obtiene el mensaje que dejó el escritor.

:::warning La memoria compartida necesita sincronización
Si varios procesos leen y escriben a la vez en la misma zona de memoria, pueden producirse condiciones de carrera. En un caso real, el acceso debería protegerse, por ejemplo, con un bloqueo de fichero (`FileChannel.lock()`), que veremos en el siguiente apartado.
:::

## Sincronización de Procesos

La sincronización de procesos se refiere a la coordinación de la ejecución de múltiples procesos para garantizar que accedan a recursos compartidos de manera controlada y evitar condiciones de carrera. Existen varias técnicas para lograr la sincronización, incluyendo semáforos, mutexes y monitores.

:::info Procesos e hilos en los ejemplos
Los semáforos, mutexes y monitores son conceptos generales que el sistema operativo ofrece tanto para procesos como para hilos. Sin embargo, las clases de Java/Kotlin que los implementan (`Semaphore`, `ReentrantLock`…) solo funcionan **dentro de una misma JVM**, es decir, entre hilos. Por eso, en los siguientes ejemplos usaremos hilos para simular procesos concurrentes. Los hilos se estudian en profundidad en el Tema 2.

Para sincronizar **procesos distintos** desde la JVM, la herramienta más habitual es el bloqueo de ficheros (`FileChannel.lock()`), que veremos al final de este apartado.
:::

Veamos cada una de estas técnicas algo más en detalle.

### Semáforos

Un semáforo es un contador que controla cuántos procesos o hilos pueden acceder a la vez a un recurso compartido. Tiene dos operaciones básicas:

- **`acquire()`** (también llamada *wait* o *P*): si el contador es mayor que 0, lo decrementa y continúa; si es 0, se bloquea hasta que otro libere un permiso.
- **`release()`** (también llamada *signal* o *V*): incrementa el contador y despierta a alguno de los que estaban esperando.

Un semáforo inicializado a 1 (**semáforo binario**) solo deja pasar a uno a la vez; uno inicializado a N permite N accesos simultáneos.

Aquí hay un ejemplo de cómo usar semáforos en Kotlin:

```kotlin
import java.util.concurrent.Semaphore
import kotlin.concurrent.thread

fun main() {
    val semaphore = Semaphore(1) // Semáforo binario

    val tareas = (1..2).map { id ->
        thread {
            semaphore.acquire()
            try {
                println("Proceso $id: Accediendo al recurso compartido")
                Thread.sleep(1000)
                println("Proceso $id: Liberando el recurso compartido")
            } finally {
                semaphore.release() // Liberar siempre, aunque haya una excepción
            }
        }
    }
    tareas.forEach { it.join() }
}
```

### Mutexes

Los mutexes (*mutual exclusion*) son similares a un semáforo binario, pero con una diferencia importante: el mutex tiene **propietario**. Solo quien lo ha bloqueado puede desbloquearlo. Un mutex puede estar bloqueado o desbloqueado; cuando alguien lo bloquea, los demás deben esperar hasta que sea desbloqueado.

Aquí hay un ejemplo de cómo usar mutexes en Kotlin:

```kotlin
import java.util.concurrent.locks.ReentrantLock
import kotlin.concurrent.thread
import kotlin.concurrent.withLock

fun main() {
    val lock = ReentrantLock()

    val tareas = (1..2).map { id ->
        thread {
            // withLock bloquea el mutex y lo desbloquea al salir del bloque
            lock.withLock {
                println("Proceso $id: Accediendo al recurso compartido")
                Thread.sleep(1000)
                println("Proceso $id: Liberando el recurso compartido")
            }
        }
    }
    tareas.forEach { it.join() }
}
```

:::warning Locks y corrutinas
Los locks de Java (`ReentrantLock`) pertenecen al **hilo** que los adquiere. Una corrutina puede suspenderse y reanudarse en otro hilo, por lo que no deben combinarse con funciones de suspensión como `delay()` dentro de un `withLock`. Para corrutinas existe `kotlinx.coroutines.sync.Mutex`, que veremos en el Tema 2.
:::

### Monitores

Los monitores son una abstracción de alto nivel para la sincronización. Un monitor es un objeto que encapsula un recurso compartido y proporciona métodos para acceder a él de manera segura. Los monitores utilizan un mutex y **variables de condición** para garantizar que solo uno pueda acceder al recurso a la vez y para que los demás esperen de forma ordenada.

Aquí hay un ejemplo de cómo usar monitores en Kotlin:

```kotlin
import java.util.concurrent.locks.Condition
import java.util.concurrent.locks.ReentrantLock
import kotlin.concurrent.thread
import kotlin.concurrent.withLock

class Monitor {
    private val lock = ReentrantLock()
    private val condition: Condition = lock.newCondition()
    private var recursoDisponible = true // Al principio el recurso está libre

    fun accederRecurso() {
        lock.withLock {
            while (!recursoDisponible) {
                condition.await()
            }
            println("Accediendo al recurso compartido")
            recursoDisponible = false
        }
    }

    fun liberarRecurso() {
        lock.withLock {
            println("Liberando el recurso compartido")
            recursoDisponible = true
            condition.signal()
        }
    }
}

fun main() {
    val monitor = Monitor()

    val tareas = (1..2).map {
        thread {
            monitor.accederRecurso()
            Thread.sleep(1000)
            monitor.liberarRecurso()
        }
    }
    tareas.forEach { it.join() }
}
```

En este ejemplo, la clase `Monitor` encapsula un recurso compartido y proporciona métodos para acceder a él de manera segura. El primero que llama a `accederRecurso()` lo ocupa; el segundo se queda esperando en `condition.await()` (lo que libera temporalmente el lock) hasta que el primero llama a `liberarRecurso()` y le avisa con `condition.signal()`.

### Sincronización entre procesos con bloqueo de ficheros

Cuando los que compiten por un recurso son **procesos distintos** (por ejemplo, dos programas que escriben en el mismo fichero), podemos usar el bloqueo de ficheros que ofrece el sistema operativo a través de `FileChannel.lock()`:

```kotlin
import java.nio.channels.FileChannel
import java.nio.file.Path
import java.nio.file.StandardOpenOption.*

fun main() {
    val pid = ProcessHandle.current().pid()
    val fichero = Path.of("/tmp/registro_compartido.txt")

    FileChannel.open(fichero, CREATE, WRITE, APPEND).use { canal ->
        println("[$pid] Esperando el bloqueo del fichero...")
        canal.lock().use { // Bloquea hasta que ningún otro proceso tenga el lock
            println("[$pid] Bloqueo obtenido, escribiendo...")
            canal.write(java.nio.ByteBuffer.wrap("Línea escrita por el proceso $pid\n".toByteArray()))
            Thread.sleep(3000) // Simula una escritura larga
        } // El bloqueo se libera al salir del bloque
        println("[$pid] Bloqueo liberado")
    }
}
```

Si lanzamos este programa dos veces a la vez, el segundo proceso esperará a que el primero libere el bloqueo antes de escribir.

Los semáforos, mutexes y monitores son herramientas esenciales para garantizar la integridad de los datos y evitar condiciones de carrera en aplicaciones concurrentes. Estas herramientas permiten coordinar el acceso a recursos compartidos y asegurar que solo un proceso pueda acceder a ellos en un momento dado. Es importante elegir la técnica de sincronización adecuada según las necesidades específicas de la aplicación y el entorno en el que se ejecuta.
