# Tema 1: Fundamentos de la Programación Concurrente y Procesos

Esta unidad introducirá los conceptos fundamentales de la ejecución paralela y la gestión del sistema operativo sobre los programas.    

## Contenidos

1. Introducción a la Programación Concurrente y Paralela
    - Características de la programación concurrente y sus ámbitos. 
    - Diferencias entre programación paralela y distribuida: ventajas e inconvenientes.
2. Gestión de Procesos por el Sistema Operativo
    - Ejecutables: procesos y servicios. 
    - Estados de un proceso y la planificación por el sistema operativo. 
    - Comandos y herramientas gráficas para la gestión de procesos (monitorización, finalización, etc.).
3. Programación con Procesos y Sincronización
    - Creación y gestión de procesos desde una aplicación. 
    - Comunicación entre procesos (pipes, sockets -breve introducción-, memoria compartida). 
    - Sincronización entre procesos. 
    - Programación de aplicaciones multiproceso sencillas.
4. Depuración y Documentación de Aplicaciones Multiproceso
    - Técnicas básicas de depuración para aplicaciones multiproceso. 
    - Importancia y métodos de documentación.

## Ejercicios prácticos

:::info
Los siguientes ejercicios están diseñados para practicar la gestión, creación, monitorización y manejo de procesos en Kotlin. Cada uno incluye una solución oculta que puedes consultar cuando lo necesites.
:::

:::tip Bash, PowerShell y CMD
Los enunciados usan comandos de bash (Linux, macOS, WSL o Git Bash), pero cada ejercicio indica también sus equivalentes en PowerShell y CMD, y las soluciones tienen una pestaña para cada intérprete (la pestaña que elijas se mantiene en todos los ejercicios). En Windows ten en cuenta que:

- `ProcessBuilder` no usa ningún intérprete: lanza directamente un ejecutable. Los comandos internos de CMD (`dir`, `echo`, `type`...) y los *cmdlets* de PowerShell (`Get-ChildItem`, `Get-Process`...) no son ejecutables, así que hay que lanzarlos a través de su intérprete: `cmd /c ...` o `powershell -Command ...`.
- Al lanzar `powershell` desde Java conviene cerrar su entrada estándar (`process.outputStream.close()`); si no, puede quedarse esperando datos y no terminar nunca.
- Si las tildes o la `ñ` aparecen mal, es por la codificación de la consola de Windows. Se arregla anteponiendo `chcp 65001 > nul &` en CMD o `[Console]::OutputEncoding = [Text.Encoding]::UTF8;` en PowerShell.
:::

### Ejercicio 1: Ejecutar un comando simple
**Enunciado:** Escribe un programa en Kotlin que ejecute el comando `ls` y muestre la salida por pantalla.

**Comandos:** bash `ls` · PowerShell `Get-ChildItem` · CMD `dir`

**Requisitos:**
- Usar `ProcessBuilder`.
- Mostrar la salida estándar del proceso.
<details>
<summary>Solución</summary>

<Tabs groupId="shell">
<TabItem value="bash" label="bash" default>

```kotlin title="Main.kt"
import java.io.BufferedReader
import java.io.InputStreamReader

fun main() {
    val process = ProcessBuilder("ls").start()
    val reader = BufferedReader(InputStreamReader(process.inputStream))
    reader.lines().forEach { println(it) }
}
```

</TabItem>
<TabItem value="powershell" label="PowerShell">

```kotlin title="Main.kt"

fun main() {

    process.outputStream.close() // Cerramos la entrada para que PowerShell no espere datos
    val reader = BufferedReader(InputStreamReader(process.inputStream))
    reader.lines().forEach { println(it) }
}
```

</TabItem>

### Ejercicio 3: Capturar errores del proceso
**Enunciado:** Escribe un programa que ejecute un comando inexistente y capture tanto la salida estándar como la de error.

**Comandos:** lanza el comando inexistente a través del intérprete: bash `bash -c comando_inexistente` · PowerShell `powershell -Command comando_inexistente` · CMD `cmd /c comando_inexistente`

**Requisitos:**
- Usar `redirectErrorStream(false)` y mostrar ambas salidas.
<details>
<summary>Solución</summary>

Lanzamos el comando a través del intérprete porque, si se pasa directamente a `ProcessBuilder`, `start()` lanza una `IOException` (el ejecutable no existe) y no llega a haber ninguna salida de error que leer. En cambio, el intérprete sí arranca y es él quien escribe el error en su salida de error.

<Tabs groupId="shell">
<TabItem value="bash" label="bash" default>

```kotlin title="Main.kt"
import java.io.BufferedReader
import java.io.InputStreamReader

fun main() {
    val pb = ProcessBuilder("bash", "-c", "comando_inexistente")
    pb.redirectErrorStream(false)
    val process = pb.start()
    val stdOut = BufferedReader(InputStreamReader(process.inputStream))
    val stdErr = BufferedReader(InputStreamReader(process.errorStream))
    println("Salida estándar:")
    stdOut.lines().forEach { println(it) }
    println("Salida de error:")
    stdErr.lines().forEach { println(it) }
}
```

</TabItem>
<TabItem value="powershell" label="PowerShell">

```kotlin title="Main.kt"
import java.io.BufferedReader
```

<TabItem value="powershell" label="PowerShell">

</TabItem>
<TabItem value="cmd" label="CMD">

### Ejercicio 6: Lanzar varios procesos en paralelo
**Enunciado:** Escribe un programa que lance tres procesos que ejecuten `sleep 1`, `sleep 2` y `sleep 3` en paralelo y muestre cuándo termina cada uno.

**Comandos:** bash `sleep N` · PowerShell `Start-Sleep -Seconds N` · CMD `ping -n N+1 127.0.0.1 > nul`

> **Nota:** El uso de hilos (`thread`) se verá en detalle en el siguiente tema. Aquí se muestra como ejemplo avanzado para quien quiera explorar cómo lanzar procesos en paralelo desde Kotlin.

**Requisitos:**
- Usar hilos para lanzar los procesos en paralelo.
<details>
<summary>Solución</summary>

<Tabs groupId="shell">
<TabItem value="bash" label="bash" default>

```kotlin title="Main.kt"
import kotlin.concurrent.thread

fun main() {
    val comandos = listOf("1", "2", "3")
    val hilos = comandos.map { segundos ->
        thread {
            val process = ProcessBuilder("sleep", segundos).start()
            process.waitFor()
            println("Proceso sleep $segundos terminado")
        }
    }
    hilos.forEach { it.join() }
}
```

</TabItem>
<TabItem value="powershell" label="PowerShell">

Arrancar PowerShell tarda alrededor de un segundo, así que los tiempos reales serán algo mayores, pero el orden de finalización se mantiene.

```kotlin title="Main.kt"

        thread {
            val process = ProcessBuilder("powershell", "-Command", "Start-Sleep -Seconds $segundos").start()
            process.outputStream.close()
            process.waitFor()
            println("Proceso Start-Sleep $segundos terminado")
        }
    }
    hilos.forEach { it.join() }
}
```

</TabItem>
<TabItem value="cmd" label="CMD">


### Ejercicio 7: Comunicación entre procesos
**Enunciado:** Escribe un programa que ejecute el comando `echo hola` y redirija su salida como entrada a otro proceso que ejecute `tr a-z A-Z` (convierte a mayúsculas).

**Comandos:** bash `echo hola` y `tr a-z A-Z` · PowerShell `Write-Output hola` y `$input | ForEach-Object { $_.ToUpper() }` · CMD `echo hola` y `findstr /n "^"` (CMD no tiene un comando para pasar a mayúsculas; `findstr /n` numera las líneas que recibe)

**Requisitos:**
- Usar streams para conectar procesos.
<details>
<summary>Solución</summary>

<Tabs groupId="shell">
<TabItem value="bash" label="bash" default>

```kotlin title="Main.kt"
import java.io.BufferedReader
import java.io.InputStreamReader

fun main() {
    val echo = ProcessBuilder("echo", "hola").start()
    val tr = ProcessBuilder("tr", "a-z", "A-Z").start()
    echo.inputStream.transferTo(tr.outputStream)
    tr.outputStream.close()
    val reader = BufferedReader(InputStreamReader(tr.inputStream))
    reader.lines().forEach { println(it) }
}
```

</TabItem>
<TabItem value="powershell" label="PowerShell">

En PowerShell, `$input` representa lo que llega por la entrada estándar. Los `$` de PowerShell se escapan con `\$` para que Kotlin no los interprete como plantillas de *string*.

```kotlin title="Main.kt"
import java.io.BufferedReader
import java.io.InputStreamReader

fun main() {
    val echo = ProcessBuilder("powershell", "-Command", "Write-Output hola").start()
    echo.outputStream.close()
    val upper = ProcessBuilder("powershell", "-Command", "\$input | ForEach-Object { \$_.ToUpper() }").start()
    echo.inputStream.transferTo(upper.outputStream)
    upper.outputStream.close()
    val reader = BufferedReader(InputStreamReader(upper.inputStream))
    reader.lines().forEach { println(it) }
}
```

</TabItem>
<TabItem value="cmd" label="CMD">

CMD no tiene ningún comando para convertir a mayúsculas, así que conectamos `echo` con `findstr /n "^"`, que numera cada línea que recibe (la salida será `1:hola`). Lo importante del ejercicio, conectar la salida de un proceso con la entrada de otro, es igual. `findstr` es un programa (no un comando interno), por eso se lanza sin `cmd /c`.

```kotlin title="Main.kt"
import java.io.BufferedReader
import java.io.InputStreamReader

fun main() {
    val echo = ProcessBuilder("cmd", "/c", "echo", "hola").start()
    val findstr = ProcessBuilder("findstr", "/n", "^").start()
    echo.inputStream.transferTo(findstr.outputStream)
    findstr.outputStream.close()
    val reader = BufferedReader(InputStreamReader(findstr.inputStream))
    reader.lines().forEach { println(it) }
}
```

</TabItem>
</Tabs>
</details>

### Ejercicio 8: Monitorizar el uso de CPU de un proceso
**Enunciado:** Escribe un programa que lance un proceso (por ejemplo, `yes > /dev/null`) y monitorice su uso de CPU durante 3 segundos usando el comando `ps`.

**Comandos:**
- bash: `yes > /dev/null` y `ps -p <pid> -o %cpu`
- PowerShell: `while ($true) {}` y `Get-Process -Id <pid> | Select-Object Id, CPU`
- CMD: `for /l %i in (0,0,1) do @rem` (bucle infinito) y `tasklist /v /fo list /fi "PID eq <pid>"`

**Requisitos:**
- Lanzar y monitorizar el proceso.
- Mostrar el uso de CPU.
<details>
<summary>Solución</summary>

<Tabs groupId="shell">
<TabItem value="bash" label="bash" default>

```kotlin title="Main.kt"
import java.io.BufferedReader
import java.io.InputStreamReader
import kotlin.concurrent.thread

fun main() {
    val process = ProcessBuilder("yes").redirectOutput(ProcessBuilder.Redirect.DISCARD).start()
    val pid = process.pid()
    repeat(3) {
        Thread.sleep(1000)
        val ps = ProcessBuilder("ps", "-p", "$pid", "-o", "%cpu").start()
        val reader = BufferedReader(InputStreamReader(ps.inputStream))
        reader.lines().forEach { println(it) }
    }
    process.destroy()
}
```

</TabItem>
<TabItem value="powershell" label="PowerShell">

La columna `CPU` de `Get-Process` es el tiempo total de CPU consumido (en segundos), no un porcentaje: si crece aproximadamente un segundo por cada segundo, el proceso está ocupando un núcleo completo.

```kotlin title="Main.kt"
import java.io.BufferedReader
import java.io.InputStreamReader

fun main() {
    // Bucle infinito que mantiene ocupada la CPU
    val process = ProcessBuilder("powershell", "-Command", "while (\$true) {}")
        .redirectOutput(ProcessBuilder.Redirect.DISCARD)
        .start()
    process.outputStream.close()
    val pid = process.pid()
    repeat(3) {
        Thread.sleep(1000)
        val ps = ProcessBuilder("powershell", "-Command", "Get-Process -Id $pid | Select-Object Id, CPU").start()
        ps.outputStream.close()
        val reader = BufferedReader(InputStreamReader(ps.inputStream))
        reader.lines().forEach { println(it) }
    }
    process.destroy()
}
```

</TabItem>
<TabItem value="cmd" label="CMD">

`tasklist` tampoco muestra un porcentaje, sino el campo `Tiempo de CPU` acumulado (h:mm:ss), que irá aumentando mientras el bucle se ejecuta.

```kotlin title="Main.kt"
import java.io.BufferedReader
import java.io.InputStreamReader

fun main() {
    // for /l con incremento 0 es un bucle infinito que mantiene ocupada la CPU
    val process = ProcessBuilder("cmd", "/c", "for", "/l", "%i", "in", "(0,0,1)", "do", "@rem")
        .redirectOutput(ProcessBuilder.Redirect.DISCARD)
        .start()
    val pid = process.pid()
    repeat(3) {
        Thread.sleep(1000)
        val tasklist = ProcessBuilder("cmd", "/c", "tasklist", "/v", "/fo", "list", "/fi", "PID eq $pid").start()
        val reader = BufferedReader(InputStreamReader(tasklist.inputStream))
        reader.lines().forEach { println(it) }
    }
    process.destroy()
}
```

</TabItem>
</Tabs>
</details>

### Ejercicio 9: Crear un proceso hijo que ejecute otro programa Kotlin
**Enunciado:** Escribe dos programas Kotlin: el primero debe lanzar el segundo como proceso hijo y mostrar su salida.
**Requisitos:**
- El programa hijo debe estar compilado previamente como un `.jar` ejecutable.
- El lanzador debe mostrar la salida del hijo y su código de salida.
<details>
<summary>Solución</summary>

```kotlin title="Hijo.kt"
fun main() {
    println("¡Hola desde el proceso hijo!")
}
```

Compilamos el hijo como un `.jar` que incluya el runtime de Kotlin (también se puede generar desde IntelliJ o con Gradle):

```bash
kotlinc Hijo.kt -include-runtime -d hijo.jar
```

```kotlin title="Lanzador.kt"
fun main() {
    // El proceso hijo es una nueva JVM que ejecuta hijo.jar
    val process = ProcessBuilder("java", "-jar", "hijo.jar")
        .redirectErrorStream(true)
        .start()

    process.inputStream.bufferedReader().lines().forEach { println("[hijo] $it") }
    println("El hijo terminó con código ${process.waitFor()}")
}
```

Tanto el comando de compilación como el lanzador funcionan igual en bash, PowerShell y CMD, porque `kotlinc` y `java` son programas y no comandos internos del intérprete.
</details>

### Ejercicio 11: Prueba unitaria con JUnit para un proceso
**Enunciado:** Escribe una función en Kotlin que ejecute un comando y devuelva su salida como String. Implementa una prueba unitaria con JUnit que verifique que al ejecutar `echo hola` la salida es "hola".

```kotlin title="ProcessUtilsTest.kt"
import org.junit.jupiter.api.Assertions.assertEquals
```

```kotlin title="ProcessUtils.kt"
import java.io.BufferedReader
import java.io.InputStreamReader
```

```kotlin title="ProcessChain.kt"
fun processStrings(inputs: List<String>): List<String> {

        val tr = ProcessBuilder("tr", "a-z", "A-Z").start()
```

**Enunciado:** Escribe un programa que cree un archivo temporal, escriba varias líneas en él usando un proceso, luego use otro proceso para contar las líneas (`wc -l`), y finalmente lea y muestre el contenido. **Comandos:**

- PowerShell: `Set-Content` (escribir), `(Get-Content ...).Count` (contar) y `Get-Content` (leer)
- CMD: `echo` (escribir), `type ... | find /c /v ""` (contar) y `type` (leer)

```kotlin title="FlujoMultiproceso.kt"
import java.io.File

fun main() {
    // 1. Crear archivo temporal
    val temp = File.createTempFile("flujo", ".txt")
    // 2. Escribir varias líneas usando un proceso
    val lines = listOf("primera línea", "segunda línea", "tercera línea")
    // printf repite el formato "%s\n" para cada argumento: una línea por elemento
    ProcessBuilder("printf", "%s\\n", *lines.toTypedArray())
        .redirectOutput(temp)
        .start()
        .waitFor()

    val wc = ProcessBuilder("wc", "-l", temp.absolutePath).start()
    val numLines = wc.inputStream.bufferedReader().readText().trim()
    println("Número de líneas: $numLines")
    // 4. Leer y mostrar el contenido
    val cat = ProcessBuilder("cat", temp.absolutePath).start()
    val contenido = cat.inputStream.bufferedReader().readText().trim()
    println("Contenido:\n$contenido")
    temp.delete()
}
```

```kotlin title="FlujoMultiproceso.kt"
fun powershell(orden: String): String {

    process.outputStream.close() // Evita que PowerShell se quede esperando entrada
    return process.inputStream.bufferedReader().readText().trim()

    val temp = File.createTempFile("flujo", ".txt")

    val lines = listOf("primera línea", "segunda línea", "tercera línea")
    // Set-Content escribe cada elemento de la lista 'a','b','c' en una línea

    powershell("Set-Content -LiteralPath '$ruta' -Encoding UTF8 -Value $valores")

    println("Número de líneas: $numLines")

}
```

<Tabs groupId="shell">

```kotlin title="MenuProcesos.kt"
import java.util.*
import java.util.logging.FileHandler
import java.util.logging.Logger
import java.util.logging.SimpleFormatter
import kotlin.concurrent.thread

fun main() {
    val logger = Logger.getLogger("MenuProcesos")
    val fileHandler = FileHandler("procesos.log", true)
    fileHandler.formatter = SimpleFormatter()
    logger.addHandler(fileHandler)
    val bgProcesses = mutableMapOf<Int, Process>()
    val scanner = Scanner(System.`in`)
    var running = true
    while (running) {
        println("\nMenú de procesos:")

            "1" -> {
                print("Comando: ")
```

### Ejercicio extra 2: Tubería configurable

**Enunciado:** Escribe un programa que lea de un fichero de texto una **tubería de comandos** (un comando por línea) y la ejecute conectando la salida estándar de cada proceso con la entrada estándar del siguiente, como hace el operador `|` de la terminal, pero desde Kotlin. El programa muestra el código de salida de cada etapa y el resultado final.

Prepara un fichero de tubería para cada intérprete. Los tres cuentan cuántos procesos con `java` en su nombre hay en ejecución:

```text title="tuberia-bash.txt"
ps -e
grep java
wc -l
```

```text title="tuberia-powershell.txt"

$input | Select-String java
($input | Measure-Object).Count
```

```text title="tuberia-cmd.txt"

findstr /i java
find /c /v ""
```

En PowerShell, `$input` representa lo que llega al proceso por su entrada estándar.

**Requisitos:**
- Uso: `encadenar <fichero> <bash|powershell|cmd>`. Se ignoran las líneas vacías del fichero. Si el fichero no existe o tiene menos de dos comandos, se muestra un error y se termina con código 1.
- Se lanzan **todas** las etapas y después se va pasando la salida de cada una a la entrada de la siguiente (`transferTo`), cerrando cada entrada al terminar para que la etapa siguiente reciba el final de los datos. La entrada de la primera etapa se cierra nada más lanzarla.
- Al final se muestra la salida de la última etapa y una línea por etapa con su comando y su código de salida.
- Si alguna etapa termina con un código distinto de 0, se indica cuál. Ten en cuenta que `grep` y `findstr` terminan con código 1 cuando no encuentran nada: el programa debe avisar, pero no tratarlo como un fallo grave.
- **Opcional:** Java permite lanzar una tubería completa con `ProcessBuilder.startPipeline(listaDeProcessBuilders)`, que conecta las etapas automáticamente y devuelve la lista de procesos. Añade un segundo modo, `encadenar-auto <fichero> <interprete>`, que haga lo mismo con este método, y compara el resultado.

**Ejemplo de ejecución:**

```text

Resultado:
2

Etapa 2: grep java    -> codigo 0
Etapa 3: wc -l        -> codigo 0

$ java -jar encadenar.jar tuberia-cmd.txt cmd      (con un fichero en el que se busca "noexiste")
Resultado:
0
Etapa 1: tasklist            -> codigo 0

```

### Ejercicio extra 3: Contador de palabras repartido

**Enunciado:** Escribe un único programa Kotlin que cuente las palabras más frecuentes de un fichero de texto grande repartiendo el trabajo entre **varios procesos hijo**. El programa tiene dos modos: el proceso **padre** divide el fichero en trozos y se los envía a los hijos por su entrada estándar, y cada proceso **hijo** cuenta las palabras de su trozo y devuelve el recuento por su salida estándar. Este ejercicio no usa comandos del sistema, así que funciona igual en Linux, macOS y Windows.

Para lanzar el propio programa como proceso hijo, puedes usar esta función (cambia `MainKt` si tu fichero no se llama `Main.kt`):

```kotlin
// Prepara un proceso que ejecuta ESTE MISMO programa con los argumentos indicados
fun procesoJava(vararg args: String): ProcessBuilder {
    val java = ProcessHandle.current().info().command().orElse("java")
    val classpath = System.getProperty("java.class.path")
    return ProcessBuilder(java, "-cp", classpath, "MainKt", *args)
}
```

Como texto de prueba puedes usar cualquier libro de dominio público en formato `.txt` (por ejemplo, de [Project Gutenberg](https://www.gutenberg.org/)).

**Modos del programa:**

| Modo | Papel | Descripción |
|------|-------|-------------|
| `contar` | Proceso hijo | Lee texto por su entrada estándar hasta el final (EOF) y escribe una línea `palabra;veces` por cada palabra distinta. |
| `repartir <fichero> <numHijos> <minLongitud>` | Proceso padre | Reparte el fichero entre `numHijos` hijos, junta sus recuentos y muestra las 10 palabras más frecuentes. |

**Requisitos:**
- **Hijo:** pasa el texto a minúsculas y lo separa en palabras usando como separador todo lo que no sea una letra (`Regex("[^\\p{L}]+")`). Si no ha recibido ninguna palabra, escribe `Sin palabras` por la salida de error y termina con código 1.
- **Padre:** lee las líneas del fichero y las divide en `numHijos` trozos consecutivos de tamaño parecido. Lanza **todos** los hijos pasándoles `MIN_LONGITUD` con `environment()`, escribe a cada uno su trozo por la entrada estándar y la cierra.
- **Padre:** después lee la salida de cada hijo **antes** de llamar a su `waitFor()` (si espera primero, un hijo con mucha salida puede quedarse bloqueado con la tubería llena) y suma los recuentos de todos en un mapa.
- **Padre:** muestra una línea por hijo (PID, líneas recibidas, palabras distintas devueltas y código de salida), el total de palabras contadas y las 10 más frecuentes. Un hijo que termine con error se indica, pero no detiene el programa.
- Comprueba tu programa ejecutando el modo `contar` directamente con todo el fichero como entrada (`java -jar palabras.jar contar < libro.txt` en bash o CMD; en PowerShell, `Get-Content libro.txt | java -jar palabras.jar contar`): la suma de todas las veces debe coincidir con el total del modo `repartir`.

### Ejercicio extra 4: Cola de trabajos con límite de ejecución

**Enunciado:** Escribe un **planificador de trabajos** por consola que ejecute trabajos como procesos hijo, pero **sin superar nunca un número máximo de trabajos a la vez**: los que no caben esperan en una cola y se lanzan en orden de llegada a medida que terminan los anteriores. Los trabajos son el propio programa lanzado en otro modo (usa la función `procesoJava` del ejercicio anterior), así que el ejercicio funciona igual en cualquier sistema.

**Modos del programa:**

| Modo | Papel | Descripción |
|------|-------|-------------|
| *(sin argumentos)* | Proceso padre | Planificador interactivo con el *prompt* `cola> `. |
| `trabajo <nombre> <segundos> <codigo>` | Proceso hijo | Escribe `<nombre>: paso <i>/<segundos>` una vez por segundo y, al terminar, `<nombre>: fin` y termina con el código indicado. |

**Comandos del planificador:**

```text
encolar <nombre> <segundos> <codigo>   Añade un trabajo al final de la cola
limite <n>                             Cambia el número máximo de trabajos a la vez (2 al empezar)
estado                                 Muestra todos los trabajos y su estado
cancelar <nombre>                      Quita un trabajo de la cola o detiene uno en ejecución
esperar                                No devuelve el control hasta que no quedan trabajos en cola ni en ejecución
salir                                  Cancela todo lo pendiente, muestra el resumen y termina
```

**Requisitos:**
- Cada trabajo tiene uno de estos estados: `EN COLA`, `EJECUTANDO`, `TERMINADO (<código>)`, `CANCELADO` o `CADUCADO`. El comando `estado` los muestra en orden de llegada y, para los que están en ejecución, añade su PID y los segundos que llevan.
- Antes de ejecutar cada comando, el planificador **revisa** los trabajos:
  - marca como terminados los que han acabado (con su código de salida);
  - destruye los que llevan más de 10 segundos en ejecución y los marca como `CADUCADO`;
  - lanza trabajos de la cola, en orden, mientras haya hueco según el límite;
  - muestra un aviso que empieza por `[cola]` cada vez que un trabajo termina, caduca o se lanza desde la cola.
- La salida de cada trabajo se añade al fichero `trabajos/<nombre>.log` mediante redirección. Todas las acciones del planificador (encolar, lanzar, terminar, cancelar, caducar) se registran con fecha y hora en `planificador.log`.
- `cancelar` sobre un trabajo en ejecución lo detiene con `destroy()` y, si a los 2 segundos sigue vivo, con `destroyForcibly()`.
- `esperar` hace la misma revisión en bucle (con una pequeña pausa entre vueltas) hasta que no quedan trabajos pendientes ni en ejecución.
- `salir` cancela los trabajos en cola y en ejecución, y muestra un resumen: cuántos han terminado bien (código 0), con error, cancelados y caducados.
- Valida los comandos y sus argumentos: nombres repetidos, números no válidos, límite menor que 1...

**Ejemplo de ejecución** (los PID cambiarán):

```text

cola> encolar informe 5 0
cola> encolar fallo 2 4
cola> encolar eterno 30 0
cola> estado

informe   EJECUTANDO (PID 6013)   1 s
fallo     EN COLA
eterno    EN COLA

[cola] fallo terminado (4); se lanza eterno
[cola] informe terminado (0)
[cola] eterno caducado tras 10 s

copia     TERMINADO (0)
informe   TERMINADO (0)
fallo     TERMINADO (4)
eterno    CADUCADO
cola> salir
Resumen: 2 correctos, 1 con error, 0 cancelados, 1 caducado
```
