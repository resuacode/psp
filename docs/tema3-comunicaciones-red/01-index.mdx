# Tema 3: Programación de Comunicaciones en Red con Sockets

En esta unidad didáctica veremos cómo las aplicaciones se comunican a través de la red haciendo uso de sockets.

    - Papeles de cliente y servidor y sus funciones.

    - Desarrollo de aplicaciones cliente y servidor básicas.

### Ejercicio 1: Servidor de Eco TCP (Básico)
**Enunciado:** Crea un servidor TCP que escuche en el puerto 5000. Cuando un cliente se conecte, el servidor debe leer el texto que envíe el cliente, convertirlo a mayúsculas y enviarlo de vuelta. El cliente debe conectarse, enviar una frase y mostrar la respuesta.
**Requisitos:**
- Usar `ServerSocket` y `Socket`.
- El servidor debe cerrarse después de atender a un cliente (iterativo simple).

<details>
<summary>Solución</summary>

```kotlin title="ServidorEco.kt"
import java.net.ServerSocket
import java.io.BufferedReader
import java.io.InputStreamReader
import java.io.PrintWriter

fun main() {
    val serverSocket = ServerSocket(5000)
    println("Servidor Eco esperando en puerto 5000...")
    
    val clientSocket = serverSocket.accept()
    val input = BufferedReader(InputStreamReader(clientSocket.getInputStream()))
    val output = PrintWriter(clientSocket.getOutputStream(), true)
    
    val mensaje = input.readLine()
    println("Recibido: $mensaje")
    
    output.println(mensaje.uppercase())
    
    clientSocket.close()
    serverSocket.close()
}
```

```kotlin title="ClienteEco.kt"

import java.io.BufferedReader
import java.io.InputStreamReader
import java.io.PrintWriter

fun main() {
    val socket = Socket("localhost", 5000)
    val output = PrintWriter(socket.getOutputStream(), true)
    val input = BufferedReader(InputStreamReader(socket.getInputStream()))
    
    output.println("hola mundo socket")
    val respuesta = input.readLine()
    println("Respuesta del servidor: $respuesta")
    
    socket.close()
}
```

### Ejercicio 2: Servidor de Hora UDP
**Enunciado:** Implementa un servidor UDP que escuche en el puerto 5001. Cuando reciba cualquier paquete (el contenido no importa), debe responder al remitente con la fecha y hora actual.
**Requisitos:**
- Usar `DatagramSocket` y `DatagramPacket`.
- El cliente debe enviar un paquete vacío para "despertar" al servidor y esperar la respuesta.

<details>
<summary>Solución</summary>

```kotlin title="ServidorHoraUDP.kt"
import java.net.DatagramPacket
import java.net.DatagramSocket
import java.time.LocalDateTime

fun main() {
    val socket = DatagramSocket(5001)
    val buffer = ByteArray(1024)
    println("Servidor UDP de Hora iniciado...")

    while (true) {
        val packet = DatagramPacket(buffer, buffer.size)
        socket.receive(packet) // Espera petición
        
        val fecha = LocalDateTime.now().toString()
        val respuestaBytes = fecha.toByteArray()
        
        val respuestaPacket = DatagramPacket(
            respuestaBytes, 
            respuestaBytes.size, 
            packet.address, 
            packet.port
        )
        
        socket.send(respuestaPacket)
        println("Hora enviada a ${packet.address}:${packet.port}")
    }
}
```

```kotlin title="ClienteHoraUDP.kt"
import java.net.DatagramPacket
import java.net.DatagramSocket
import java.net.InetAddress

fun main() {
    val socket = DatagramSocket()
    val direccion = InetAddress.getByName("localhost")
    val buffer = ByteArray(0) // Paquete vacío
    
    // Enviar solicitud
    val packet = DatagramPacket(buffer, buffer.size, direccion, 5001)
    socket.send(packet)
    
    // Recibir respuesta
    val bufferRx = ByteArray(1024)
    val packetRx = DatagramPacket(bufferRx, bufferRx.size)
    socket.receive(packetRx)
    
    val hora = String(packetRx.data, 0, packetRx.length)
    println("Hora del servidor: $hora")
    
    socket.close()
}
```
</details>

### Ejercicio 3: Servidor TCP Multihilo (Adivina el número)
**Enunciado:** Crea un servidor que genere un número aleatorio entre 1 y 100 para cada cliente que se conecte. El cliente enviará números intentando adivinarlo. El servidor responderá "Mayor", "Menor" o "Correcto". El servidor debe poder atender a múltiples clientes a la vez.
**Requisitos:**
- Usar hilos (`thread`) para manejar cada conexión de cliente.
- El servidor no debe detenerse nunca.

<details>
<summary>Solución</summary>

```kotlin title="ServidorAdivina.kt"
import java.net.ServerSocket
import java.net.Socket
import java.io.BufferedReader
import java.io.InputStreamReader
import java.io.PrintWriter
import kotlin.concurrent.thread
import kotlin.random.Random

fun main() {
    val serverSocket = ServerSocket(5002)
    println("Servidor 'Adivina el número' iniciado...")

    while (true) {
        val clientSocket = serverSocket.accept()
        thread {
            manejarCliente(clientSocket)
        }
    }
}

fun manejarCliente(socket: Socket) {
    try {
        val input = BufferedReader(InputStreamReader(socket.getInputStream()))
        val output = PrintWriter(socket.getOutputStream(), true)
        
        val numeroSecreto = Random.nextInt(1, 101)
        println("Cliente conectado. Número secreto: $numeroSecreto")
        
        output.println("Adivina el número (1-100):")
        
        var linea: String?
        while (input.readLine().also { linea = it } != null) {
            val intento = linea?.toIntOrNull()
            
            if (intento == null) {
                output.println("Por favor, envía un número válido.")
                continue
            }
            
            when {
                intento < numeroSecreto -> output.println("Mayor")
                intento > numeroSecreto -> output.println("Menor")
                else -> {
                    output.println("Correcto")
                    break // Terminar conexión
                }
            }
        }
    } catch (e: Exception) {
        println("Error: ${e.message}")
    } finally {
        socket.close()
    }
}
```

```kotlin title="ClienteAdivina.kt"
import java.net.Socket
import java.io.BufferedReader
import java.io.InputStreamReader
import java.io.PrintWriter

fun main() {
    val socket = Socket("localhost", 5002)
    val output = PrintWriter(socket.getOutputStream(), true)
    val input = BufferedReader(InputStreamReader(socket.getInputStream()))
    
    // Leer mensaje inicial del servidor
    println(input.readLine())
    
    val scanner = java.util.Scanner(System.`in`)
    
    while (true) {
        print("Tu intento: ")
        val intento = scanner.nextLine()
        
        output.println(intento)
        val respuesta = input.readLine()
        println("Servidor: $respuesta")
        
        if (respuesta == "Correcto") {
            println("¡Ganaste!")
            break
        }
    }
    
    socket.close()
}
```
</details>

### Ejercicio 4: Chat Grupal (Broadcast)
**Enunciado:** Implementa un servidor de chat donde múltiples clientes puedan conectarse. Cuando un cliente envía un mensaje, el servidor debe retransmitirlo a todos los demás clientes conectados.
**Requisitos:**
- El servidor debe mantener una lista de los sockets de los clientes conectados.
- Usar `synchronized` o una estructura thread-safe para gestionar la lista de clientes.
- Cuando un cliente se desconecta, debe eliminarse de la lista.

<details>
<summary>Solución</summary>

```kotlin title="ServidorChat.kt"
import java.net.ServerSocket
import java.net.Socket
import java.io.PrintWriter
import java.util.Scanner
import kotlin.concurrent.thread

val clientes = ArrayList<PrintWriter>()

fun main() {
    val serverSocket = ServerSocket(5003)
    println("Servidor de Chat iniciado en puerto 5003...")

    while (true) {
        val clientSocket = serverSocket.accept()
        val writer = PrintWriter(clientSocket.getOutputStream(), true)
        
        synchronized(clientes) {
            clientes.add(writer)
        }
        
        thread {
            try {
                val scanner = Scanner(clientSocket.getInputStream())
                while (scanner.hasNextLine()) {
                    val mensaje = scanner.nextLine()
                    println("Difundiendo: $mensaje")
                    broadcast(mensaje)
                }
            } catch (e: Exception) {
                // Cliente desconectado
            } finally {
                synchronized(clientes) {
                    clientes.remove(writer)
                }
                clientSocket.close()
            }
        }
    }
}

fun broadcast(mensaje: String) {
    synchronized(clientes) {
        for (writer in clientes) {
            writer.println(mensaje)
        }
    }
}
```

```kotlin title="ClienteChat.kt"
import java.net.Socket
import java.io.BufferedReader
import java.io.InputStreamReader
import java.io.PrintWriter
import kotlin.concurrent.thread

fun main() {
    val socket = Socket("localhost", 5003)
    val output = PrintWriter(socket.getOutputStream(), true)
    val input = BufferedReader(InputStreamReader(socket.getInputStream()))
    
    println("Conectado al chat. Escribe tus mensajes:")
    
    // Hilo para recibir mensajes
    thread {
        try {
            var mensaje: String?
            while (input.readLine().also { mensaje = it } != null) {
                println("\nMensaje: $mensaje")
                print("> ")
            }
        } catch (e: Exception) {
            println("Desconectado del servidor.")
        }
    }
    
    // Hilo principal para enviar mensajes
    val scanner = java.util.Scanner(System.`in`)
    while (scanner.hasNextLine()) {
        val mensaje = scanner.nextLine()
        output.println(mensaje)
        print("> ")
    }
    
    socket.close()
}
```
</details>

### Ejercicio 5: Transferencia de Archivos (Binario)
**Enunciado:** Crea un cliente que lea un archivo local (puedes crear un archivo de texto de prueba) y lo envíe a un servidor. 
El servidor debe recibir los datos y guardarlos en un nuevo archivo con el nombre "copia_recibida.txt".

**Requisitos:**
- Usar flujos binarios (`InputStream`/`OutputStream`), no de texto (`Reader`/`Writer`), para soportar cualquier tipo de archivo (imágenes, pdf, etc.).
- Usar un buffer de bytes para la transferencia eficiente.

<details>
<summary>Solución</summary>

```kotlin title="ServidorArchivo.kt"
import java.net.ServerSocket
import java.io.FileOutputStream

fun main() {
    val serverSocket = ServerSocket(5004)
    println("Esperando archivo en puerto 5004...")
    
    val socket = serverSocket.accept()
    val input = socket.getInputStream()
    val fileOutput = FileOutputStream("copia_recibida.txt")
    
    val buffer = ByteArray(4096)
    var bytesRead: Int
    
    // Leer del socket y escribir en archivo
    while (input.read(buffer).also { bytesRead = it } != -1) {
        fileOutput.write(buffer, 0, bytesRead)
    }
    
    println("Archivo recibido y guardado.")
    
    fileOutput.close()
    socket.close()
    serverSocket.close()
}
```

```kotlin title="ClienteArchivo.kt"
import java.net.Socket
import java.io.FileInputStream
import java.io.File

fun main() {
    val archivo = File("prueba.txt") // Asegúrate de que este archivo exista
    if (!archivo.exists()) {
        archivo.writeText("Hola, este es un archivo de prueba para enviar por red.")
    }

    val socket = Socket("localhost", 5004)
    val fileInput = FileInputStream(archivo)
    val output = socket.getOutputStream()
    
    val buffer = ByteArray(4096)
    var bytesRead: Int
    
    println("Enviando archivo...")
    while (fileInput.read(buffer).also { bytesRead = it } != -1) {
        output.write(buffer, 0, bytesRead)
    }
    
    println("Archivo enviado.")
    
    fileInput.close()
    socket.close()
}
```
</details>

### Ejercicio 6: Cliente HTTP Manual
**Enunciado:** Implementa un programa que actúe como un navegador web muy básico. 
Debe conectarse al servidor `example.com` en el puerto 80, enviar una petición HTTP GET manual y mostrar el código HTML que devuelve el servidor.

**Requisitos:**
- No usar librerías HTTP (como OkHttp o Ktor), solo `Socket`.
- La petición debe seguir el formato del protocolo HTTP:
  ```
  GET / HTTP/1.1
  Host: example.com
  Connection: close
  (línea vacía)
  ```

<details>
<summary>Solución</summary>

```kotlin title="ClienteHTTP.kt"
import java.net.Socket
import java.io.PrintWriter
import java.io.BufferedReader
import java.io.InputStreamReader

fun main() {
    val host = "example.com"
    val puerto = 80
    
    val socket = Socket(host, puerto)
    val output = PrintWriter(socket.getOutputStream(), true)
    val input = BufferedReader(InputStreamReader(socket.getInputStream()))
    
    // Enviar cabeceras HTTP
    output.println("GET / HTTP/1.1")
    output.println("Host: $host")
    output.println("Connection: close")
    output.println() // Línea vacía importante para indicar fin de cabeceras
    
    // Leer respuesta
    var linea: String?
    while (input.readLine().also { linea = it } != null) {
        println(linea)
    }
    
    socket.close()
}
```
</details>

### Ejercicio extra 1: Agenda telefónica por TCP

**Enunciado:** Escribe un servidor TCP que guarde una agenda de contactos en memoria y un cliente de consola para usarla. A diferencia del servidor de eco, aquí cada cliente mantiene **una conversación** con el servidor: envía varios comandos por la misma conexión hasta que decide salir.

**Protocolo** (una línea por mensaje, puerto 6100):

```text
ALTA <nombre> <telefono>   ->  OK alta de <nombre>        | ERROR ya existe
BUSCA <nombre>             ->  OK <telefono>              | ERROR no existe
BAJA <nombre>              ->  OK baja de <nombre>        | ERROR no existe
LISTA                      ->  OK <n> <nombre1>=<tel1>,<nombre2>=<tel2>,...   (OK 0 si está vacía)
SALIR                      ->  OK adios   (y el servidor cierra la conexión)
<cualquier otra cosa>      ->  ERROR comando desconocido
```

**Requisitos:**
- El servidor atiende a **un cliente cada vez** (sin hilos): cuando un cliente sale, pasa a atender al siguiente. La agenda se mantiene entre clientes.
- El servidor muestra por consola cada conexión (dirección y puerto del cliente), cada comando recibido y cada desconexión. Si un cliente se desconecta sin enviar `SALIR`, el servidor no debe terminar con error: simplemente pasa al siguiente.
- El teléfono debe tener 9 dígitos; si no, el servidor responde `ERROR telefono no valido`.
- El cliente lee comandos del teclado, los envía, muestra la respuesta y termina al enviar `SALIR`. Si no puede conectar con el servidor, muestra un mensaje claro en lugar de la excepción.
- Prueba el servidor también sin tu cliente, con `nc` o `telnet` (ver la tabla del principio).

**Ejemplo de ejecución:**

### Ejercicio extra 2: Estaciones de calidad del aire por UDP

**Enunciado:** Varias estaciones de medición envían periódicamente el nivel de contaminación (índice de 0 a 500) a un servidor central por **UDP**. El servidor guarda las lecturas y responde a consultas sobre la media de cada estación. Como UDP no garantiza la entrega, el cliente que consulta debe **reintentar** si no recibe respuesta.

**Protocolo** (puerto 6200, un datagrama por mensaje):

```text
LECTURA;<estacion>;<valor>   ->  (sin respuesta)
CONSULTA;<estacion>          ->  MEDIA;<estacion>;<media con 1 decimal>;<numLecturas>  |  ERROR;sin datos de <estacion>
```

**Requisitos:**
- **Servidor:** recibe datagramas en un bucle y distingue el tipo de mensaje. Ignora (mostrando un aviso) las lecturas con un valor fuera del rango 0-500 o mal formadas. Responde las consultas a la dirección y el puerto desde los que llegaron.
- **Servidor:** si se arranca con el argumento `--perdidas`, ignora al azar el 40 % de las consultas (sin responder) para simular pérdidas en la red y poder probar los reintentos.
- **Cliente, modo `emitir <estacion> <numLecturas>`:** envía las lecturas, con valores al azar, una cada 200 ms, y muestra cada una.
- **Cliente, modo `consultar <estacion>`:** envía la consulta y espera la respuesta como máximo 1 segundo (`setSoTimeout`). Si no llega, lo vuelve a intentar hasta 3 veces en total, mostrando cada intento, y al final indica si ha obtenido respuesta o no.
- Comprueba con los comandos de la tabla del principio que el puerto UDP está abierto mientras el servidor funciona.

**Ejemplo de ejecución:**

```text

Enviada lectura centro = 64
Enviada lectura centro = 99
Enviada lectura centro = 143
```

### Ejercicio extra 3: Subasta en directo

**Enunciado:** Escribe un servidor TCP **multihilo** para una subasta en directo y su cliente. Varios pujadores se conectan a la vez, pujan por un mismo objeto y reciben al momento las pujas de los demás. La subasta se cierra sola cuando pasan unos segundos sin pujas nuevas.

**Protocolo** (puerto 6300):

```text
Al conectar, el cliente envía:  NOMBRE <nombre>   ->  BIENVENIDO <objeto> precio actual <precio>  |  ERROR nombre en uso
PUJA <cantidad>                 ->  OK puja aceptada  |  RECHAZADA minimo <precio actual + 5>
ESTADO                          ->  ESTADO <precio actual> <ganador provisional o "nadie">
SALIR                           ->  OK adios

El servidor envía a todos los demás clientes, sin que lo pidan:
AVISO <nombre> puja <cantidad>
FIN <ganador> <cantidad>        (al cerrar la subasta; después cierra todas las conexiones)
```

**Requisitos:**
- Uso del servidor: `servidor <objeto> <precioSalida> <segundosSinPujas>`.
- El servidor atiende a cada cliente en su propio hilo. La lista de clientes conectados se guarda en una colección segura para hilos y se usa para enviar los avisos a todos.
- El precio actual y el ganador provisional se comparten entre todos los hilos: comprobar que una puja supera el mínimo y aceptarla debe ser **una operación atómica**, para que dos pujas simultáneas no puedan aceptarse con el mismo precio.
- Un hilo temporizador (o un `ScheduledExecutorService`) cierra la subasta cuando pasan `segundosSinPujas` segundos sin pujas aceptadas: envía `FIN` a todos, cierra las conexiones y termina el servidor.
- El cliente necesita **dos hilos**: uno lee del teclado y envía los comandos, y otro escucha los mensajes del servidor y los muestra en cuanto llegan. Al recibir `FIN`, el cliente termina.
- Si un cliente se desconecta de golpe, el servidor lo quita de la lista sin afectar al resto.

**Ejemplo de ejecución** (dos clientes a la vez):

```text
[cliente ana]                               [cliente luis]
> NOMBRE ana                                > NOMBRE luis
BIENVENIDO reloj precio actual 50           BIENVENIDO reloj precio actual 50
> PUJA 60                                   AVISO ana puja 60
OK puja aceptada                            > PUJA 62
                                            RECHAZADA minimo 65
AVISO luis puja 70                          > PUJA 70
                                            OK puja aceptada
> ESTADO
ESTADO 70 luis
FIN luis 70                                 FIN luis 70
```

### Ejercicio extra 4: ParkNet, aparcamiento inteligente

**Enunciado:** Un aparcamiento de varias plantas quiere un sistema en red para gestionar sus entradas y salidas desde varias cabinas a la vez. Las consultas rápidas de plazas libres (por ejemplo, para el panel de la entrada) se hacen por **UDP**, y las operaciones que modifican datos, por **TCP** con un servidor **multihilo**. El servidor lee su configuración de un fichero y registra todas las operaciones en un log.

**Ficheros de configuración:**

```text title="config.txt"
puerto_tcp=6400
puerto_udp=6401
plantas=plantas.txt
log=parknet.log
euros_minuto=0.05
```

```text title="plantas.txt"
P0;10
P1;8
P2;5
```

Para que las pruebas sean rápidas, **cada segundo real cuenta como un minuto** al calcular el importe. El importe mínimo es de 1 €.

**Protocolo:**

```text
UDP  LIBRES              ->  P0=10;P1=8;P2=5
UDP  LIBRES;<planta>     ->  <planta>=<libres>  |  ERROR;planta no existe

TCP  ENTRAR <matricula>  ->  OK planta <planta>  |  ERROR completo  |  ERROR ya esta dentro
TCP  SALIR <matricula>   ->  OK importe <euros con 2 decimales>  |  ERROR no esta dentro
TCP  BUSCAR <matricula>  ->  OK <planta> desde <hh:mm:ss>  |  ERROR no esta dentro
TCP  LISTAR              ->  OK <n> <matricula1>:<planta1>,<matricula2>:<planta2>,...
TCP  FIN                 ->  OK adios
```

**Requisitos del servidor:**
- Lee `config.txt` y el fichero de plantas. Si falta algún dato, usa valores por defecto y lo indica al arrancar.
- Atiende UDP y TCP a la vez (cada uno en su propio hilo) y cada cliente TCP en su propio hilo.
- `ENTRAR` asigna la **primera planta con plazas libres** en el orden del fichero. La asignación debe ser atómica: aunque muchas cabinas pidan entrar a la vez, nunca puede haber más coches que plazas en una planta ni dos entradas con la misma matrícula.
- Registra cada operación en el log con fecha, hora, dirección del cliente, comando y respuesta.

**Requisitos del cliente:**
- Menú por consola con las opciones: consultar plazas libres (UDP), consultar una planta (UDP), entrar, salir, buscar, listar (TCP) y salir del programa.
- Valida la matrícula antes de enviarla (4 números y 3 letras, por ejemplo `1234ABC`).
- Usa un tiempo máximo de espera de 2 segundos en UDP e informa si el servidor no responde.
- **Modo de prueba de carga** `simular <numCabinas>`: lanza `numCabinas` hilos que intentan entrar a la vez con matrículas distintas, y al terminar comprueba con `LIBRES` que no se ha superado la capacidad de ninguna planta y que el número de entradas aceptadas coincide con las plazas ocupadas.
