# Proyectos: Servicios en Red y APIs

Estos proyectos están diseñados para aplicar los conocimientos sobre consumo de servicios web (APIs REST) y la implementación de seguridad en aplicaciones. El objetivo es construir aplicaciones conectadas que consuman datos reales de internet y los presenten de forma atractiva, además de un proyecto enfocado específicamente en la seguridad.

:::info Nota importante
Se proponen 4 proyectos. Dos de ellos deben desarrollarse como aplicaciones **Kotlin Multiplatform (KMP) para Escritorio (Windows)**. Los otros dos deben ser **KMP para Escritorio (Windows) y Android**.
:::

---

## Proyecto 1: Gestor de Contraseñas "Fortress" 🛡️

**Plataformas:** Kotlin Multiplatform (Escritorio Windows + Android)
**Enfoque:** Seguridad y Criptografía

### Descripción

Desarrolla una "bóveda" digital segura para almacenar contraseñas. La aplicación nunca debe guardar las contraseñas en texto plano. Todo debe estar cifrado utilizando una "Contraseña Maestra" que solo el usuario conoce y que **nunca** se guarda en el dispositivo.

### Funcionalidades obligatorias

#### Seguridad y Criptografía
1.  **Cifrado AES-256:** La base de datos local (o archivo JSON) debe estar cifrada completamente.
2.  **Derivación de Claves (PBKDF2/Argon2):** La clave AES no es la contraseña maestra, sino una derivada de ella usando un algoritmo lento con *salt*.
3.  **Memoria Segura:** Intentar limpiar las variables que contienen la contraseña maestra de la memoria RAM lo antes posible.

#### Interfaz Gráfica
- **Login:** Pantalla única pidiendo la contraseña maestra para descifrar la bóveda.
- **Lista de Credenciales:** Vista con buscador para filtrar por sitio web.
- **Generador de Contraseñas:** Herramienta para crear passwords fuertes (longitud, símbolos, etc.).
- **Portapapeles Seguro:** Botón para copiar contraseña que se borre del portapapeles automáticamente a los 30 segundos.

#### Requisitos Técnicos
- **KMP:** Lógica de cifrado compartida.
- **Persistencia:** Uso de SQLDelight o archivos planos, pero siempre cifrados.

## Proyecto 2: Explorador de la NASA (Astronomy Picture of the Day) 🚀

**Plataformas:** Kotlin Multiplatform (Escritorio Windows + Android)
**Enfoque:** Consumo de API REST + Imágenes

### Descripción

Crea una aplicación que permita explorar la "Imagen astronómica del día" (APOD) que la NASA publica a diario desde 1995, junto con la explicación de un astrónomo. La app consumirá la API pública APOD de la NASA.

:::note
Este proyecto usaba antes la API de fotos de los rovers de Marte (*Mars Rover Photos*), pero ese servicio ya no está disponible.
:::

### Funcionalidades obligatorias

#### Comunicación y Red
1.  **API Client:** Implementar un cliente HTTP (Ktor o Retrofit) para consumir la [API APOD de la NASA](https://api.nasa.gov/) (endpoint `https://api.nasa.gov/planetary/apod`).
2.  **Filtrado:** Permitir al usuario consultar la imagen de una fecha concreta (`date`), de un rango de fechas (`start_date` y `end_date`) o un número de imágenes aleatorias (`count`).
3.  **Carga de Imágenes:** Descargar y mostrar las imágenes de forma asíncrona (usando Coil 3 o Kamel). Hay que tener en cuenta que algunos días el contenido es un vídeo (campo `media_type`) y mostrarlo de forma adecuada (miniatura o enlace).

#### Interfaz Gráfica
- **Galería:** Grid de imágenes con scroll infinito o paginación (por ejemplo, cargando semana a semana hacia atrás).
- **Detalle:** Al pulsar una imagen, verla en pantalla completa con su información (título, fecha, explicación y autoría/copyright).
- **Favoritos:** Guardar localmente las imágenes favoritas.

#### Requisitos Técnicos
- **API Key:** Gestionar la API Key de forma segura (no subirla al repo público). La clave `DEMO_KEY` solo sirve para pruebas porque tiene un límite de peticiones muy bajo; hay que solicitar una clave gratuita en [api.nasa.gov](https://api.nasa.gov/).
- **Manejo de Errores:** Mostrar mensajes amigables si la API falla, si se supera el límite de peticiones (código 429) o no hay internet.

## Proyecto 3: Buscador de Películas y Series (OMDb API) 🎬

**Plataformas:** Kotlin Multiplatform (Solo Escritorio Windows)
**Enfoque:** Consumo de API REST + Búsqueda

### Descripción

Desarrolla una aplicación de escritorio para buscar información sobre películas y series utilizando la Open Movie Database (OMDb).

### Funcionalidades obligatorias

#### Comunicación y Red
1.  **Búsqueda en Tiempo Real:** Consumir la [OMDb API](https://www.omdbapi.com/) para buscar títulos mientras el usuario escribe (con debounce para no saturar).
2.  **Detalles:** Obtener información extendida: sinopsis, director, actores, premios y puntuaciones (Rotten Tomatoes, IMDB).

#### Interfaz Gráfica (Compose Multiplatform (escritorio))
- **Barra de Búsqueda:** Prominente en la parte superior.
- **Lista de Resultados:** Tarjetas con el póster y el título.
- **Panel Lateral de Detalle:** Al seleccionar una película, mostrar toda la información a la derecha.
- **Exportar:** Botón para generar un PDF o TXT con la ficha de la película seleccionada.

#### Requisitos Técnicos
- **Serialización:** Mapeo complejo de JSON a objetos Kotlin.
- **Cache:** Guardar las últimas 10 búsquedas para acceso rápido offline.

## Proyecto 4: Dashboard de Calidad del Aire (OpenWeatherMap / AQICN) 🌍

**Plataformas:** Kotlin Multiplatform (Solo Escritorio Windows)
**Enfoque:** Consumo de API REST + Visualización de Datos Ambientales

### Descripción

Una aplicación de escritorio para monitorizar la calidad del aire y las condiciones meteorológicas en diferentes ciudades del mundo en tiempo real, ideal para personas con alergias o interés ambiental.

### Funcionalidades obligatorias

#### Comunicación y Red
1.  **Datos Ambientales:** Consumir la [Air Quality Open Data Platform (AQICN)](https://aqicn.org/api/) o OpenWeatherMap para obtener el índice de calidad del aire (AQI), PM2.5, PM10 y temperatura.
2.  **Geolocalización IP:** Usar una API gratuita de IP-to-Location para detectar la ciudad aproximada del usuario al iniciar.

#### Interfaz Gráfica (Compose Multiplatform (escritorio))
- **Mapa de Calor (Simplificado):** O una lista de estaciones de medición cercanas con códigos de colores (Verde=Bueno, Rojo=Peligroso).
- **Gráficos Históricos:** Mostrar la evolución de la contaminación en las últimas 24 horas.
- **Alertas:** Notificación visual si el nivel de contaminación supera un umbral seguro en la ciudad seleccionada.

#### Requisitos Técnicos
- **Manejo de JSON Anidado:** Las respuestas de estas APIs suelen tener estructuras complejas que requieren un buen diseño de las Data Classes.
- **Refresco Periódico:** Actualización de datos cada 30 minutos.
